# Pareto Code

基于[参赛方案](AI应用大赛参赛方案介绍.md)实现的 AI 效费比选型 MVP。以 **Python 代码审查**为首个完整场景，将任务效果、每任务费用、完整执行时间放在一起比较，找出三维帕累托前沿。

**Python 3.11+，无运行依赖，无需 API Key，可离线运行。**

## 启动

在项目目录执行：

```bash
python3 -m pareto.server
```

打开 **http://127.0.0.1:8000**。

首次启动会创建 `var/pareto.sqlite3`，并添加 18 条**合成演示记录**。示例中所有模型系列、档位、评分、费用与耗时均不是实测、真实版本或当前报价；初始真实评测库为空。数据持久化到 SQLite，重启保留，演示数据不会重复初始化。

```bash
# 指定端口和数据库位置
python3 -m pareto.server --port 8080 --db var/my-team.sqlite3

# 新数据库不添加演示记录
python3 -m pareto.server --no-demo --db var/real-only.sqlite3
```

用 `Ctrl+C` 停止。数据文件已加入 `.gitignore`。备份数据库时先停止服务，再复制 `var/` 目录。

## 已实现的闭环

1. **智能选型**：设置单任务预算、完整任务耗时上限、最低效果和月任务量；绘制可切换费用 / 耗时横轴的交互气泡图，按全部三个维度计算前沿。悬停、点击或键盘聚焦可查看数据。
2. **三档推荐**：约束满足后，在前沿上选择省钱、均衡、效果三档，提供确定性解释；无解时明确提示，可验证仅调整一个约束就有解时提供快捷调整。
3. **基准测算**：选择惯用配置，仅在效果不低于基准且符合全部约束的方案中估算月度节省，不拿质量下降换来的差额冒充节省。
4. **评测数据**：JSON / CSV 校验、预览、事务性追加导入；保留版本、Agent、推理强度、供应商、来源、时间、样本量和统计口径。支持来源详情、全部快照和导出。
5. **评测工作台**：导出固定任务及结果模板，提交实际执行日志，在本机按规则评分；保留逐题原始输出、起止时间、费用、缺陷标签与评分证据，导入后直接参与选型。
6. **口径隔离**：真实与合成数据、API 账单与订阅摊销、不同任务集或评分方法严格分组。缺失指标不补零，历史快照不参与当前比较，并说明排除原因。
7. **可交付结果**：导出包含约束、来源、前沿、推荐理由和测算假设的 JSON 选型报告，或导出 CSV 对比表。页面适配桌面与手机。

这版不调用外部模型、不采集公开榜单、不产生 API 消费；快捷需求填写与推荐解释都明确使用本地规则。AI 主观评分、自动 API 执行评测、多场景任务集和自动刷新第三方数据留待后续迭代。

## 完成一次真实评测

1. 进入「评测工作台」，下载任务包和结果模板。固定测试集为 `code-review-v1`，包含 8 道 Python 代码审查题，其中 2 道无缺陷题。任务包不含标准答案；标准答案在本机评分器中。
2. 对同一待测配置逐题执行。每题独立发起，使用相同系统提示和题目要求，避免把题解或其他模型响应带入上下文。将模型名、明确版本、Agent（含版本）、推理强度、供应商及渠道填入 `config`。
3. 在 `responses` 里填写全部 8 题的实际记录：
   - `task_id`：模板中的题目 ID，不可遗漏或重复。
   - `started_at`：任务发起时间；`finished_at`：**完整结果返回时间**。均使用带时区的 ISO 8601，例如 `2026-11-03T14:00:00+08:00`。不是首 token 延迟，也不是员工选型耗时。
   - `output`：原始响应文本或原始 JSON 对象。符合要求的结构为 `{"issues": [{"line": 1, "category": "mutable-default"}]}`；无缺陷为 `{"issues": []}`。保留失败和格式错误的响应，评分器将格式错误记 0 分，不能删掉失败题。
   - API 的 `cost_cny`：这一题的真实账单人民币费用，包括所有计费环节。美元账单需自行按统一汇率换算，并在 `cost_notes` 中注明。Token 自算时请纳入推理、缓存等费用差异。
4. 在页面上传结果文件，点击「规则评分」，检查分数、平均费用、平均完整耗时。每题按缺陷 `(行号, 类型)` 的 F1 评分，8 题均值 × 100；错误定位、漏报和误报会降低分数。评分器不执行模型生成的代码。
5. 确认费用口径与数据来源后，点击「导入并选型」。切到真实评测组后，按需求调整约束。完成不同配置的同题评测，即可比较它们的前沿与费用。

会员订阅评测需将 `config.channel` 改为 `subscription`，补充 `config.monthly_fee_cny`；可在结果文件顶层填写 `monthly_tasks`（默认 500）。逐题 `cost_cny` 可留空。工作台按月费 / 任务量分摊，选型页更改预计任务量后重新计算。**摊销不是边际费用，也不保证会员调用额度。**

固定公开小样本只反映当前任务集，不能代表通用编码能力，也不能杜绝数据污染或刷分。后续需增加业务隐藏集、重复运行和人工抽查。

## 导入已有评测

进入「评测数据 → 导入评测数据」，选择 JSON / CSV 或粘贴内容，先校验预览，再确认入库。每次最多 500 条、请求最多 2 MiB；重复 ID 拒绝整批，不覆盖旧记录。

JSON 支持单条对象、数组或 `{"records": [...]}`。CSV 用相同字段作为表头，支持 UTF-8 BOM、引号与换行。可从页面下载字段模板，或参考 [examples/record.template.json](examples/record.template.json)。模板中的数据必须替换成真实值；也可先导出内置演示数据了解结构。

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一快照 ID，1–100 位字母、数字、点、下划线、连字符 |
| `scenario` | MVP 固定为 `code-review` |
| `suite` | 任务集及版本，如 `code-review-v1`；不同任务集不能混用 |
| `score_method` | 评分标准及版本；内置为 `issue-f1-v1` |
| `latency_method` | 耗时口径；内置为 `end-to-end-v1` |
| `model`, `model_version` | 模型名称和实际版本，不使用空版本 |
| `agent`, `reasoning`, `provider` | Agent、推理强度、供应商 / 使用渠道 |
| `channel` | `api` 或 `subscription` |
| `cost_method` | API 用 `api-billed-cny-v1`；订阅用 `subscription-amortized-cny-v1` |
| `quality` | 0–100 分，方向为越高越好 |
| `cost_cny` | 平均每任务人民币费用，可为 0；订阅选型时由月费重新摊销 |
| `latency_seconds` | 从发起到完整返回的平均执行秒数，必须大于 0 |
| `monthly_fee_cny` | 订阅必填；API 为 `null` / 空单元格 |
| `sample_size` | 完成的任务样本数，正整数；内置任务集必须为 8 的倍数 |
| `measured_at` | 带时区的评测快照时间 |
| `dataset_kind` | 真实数据 `measured`；合成演示 `demo` |
| `source_type` | `self-built`、`third-party` 或 `synthetic`；合成来源只能放入演示库 |
| `source_name`, `source_url` | 来源名称和链接；第三方必须提供 http(s) 链接 |
| `cost_notes` | 人民币费用统计 / 折算方法，必填 |
| `notes` | 可选的任务范围、局限或备注 |
| `task_results` | 可选的内置评分证据；导入时重新验证规则评分和汇总一致性 |

费用、质量或执行时间暂缺时允许空值，但该记录会单独注明「缺少指标」，不参加选型。不要用 0 代替未知费用。不同任务集、评分、时间或费用口径会自动分组；选择后才能在组内比较。当前仅 `end-to-end-v1` 完整耗时可参加前沿；首 token 时间等未对齐数据会单独排除。

同组内，模型、版本、Agent、推理强度和供应商均相同的配置，使用时间最新的快照。即使新快照缺指标，也不会自动退回旧数据；旧记录仍在数据页可查。

## 推荐计算

配置 A 支配配置 B，当且仅当：

```text
A.效果 >= B.效果
A.费用 <= B.费用
A.耗时 <= B.耗时
并且至少一项严格更优。
```

没有被其他配置支配的点组成前沿；相等点不互相支配。图只投影两个坐标，耗时用气泡大小表示；因此不把三维前沿错误连成二维曲线。

满足用户约束后，省钱档取费用最低者，效果档取效果最高者。均衡档对可行前沿内的三个目标计算距各自最优值的归一化差距，选择**最大差距最小**者；某维度没有跨度时，其差距为 0。没有隐藏的综合榜单权重，规则结果不冒充 AI 建议。

## 验证

```bash
# 核心算法、评分、导入、持久化和 HTTP 接口：61 项
python3 -m unittest discover -v

# JavaScript 语法
node --check pareto/static/app.js

# 可选：真实浏览器操作验证，需 Node 22+ 与 Chromium
node scripts/browser-smoke.mjs
```

浏览器脚本自动创建临时数据库和隔离浏览器，验证初始推荐、无解、快捷输入、API / 订阅隔离与任务量摊销、导入预览和重复拒绝、HTML 转义、评分入库与刷新持久化、键盘详情及四个页面的手机布局。测试数据不会写入你的工作数据库。截图输出到被忽略的 `test-results/`，结束时关闭测试进程。

`PYTHON` 和 `CHROMIUM_BIN` 可指定浏览器测试所用可执行文件。测试服务器需要允许绑定本机随机端口。

## 结构和部署边界

```text
pareto/
  domain.py       数据校验、比较分组、三维前沿和推荐
  store.py        SQLite 与事务导入
  benchmark.py    固定任务、规则评分与逐题证据校验
  server.py       HTTP API 与静态资源服务
  data/demo.json  明确标注的合成演示数据
  static/         原生 HTML / CSS / JavaScript 界面
tests/            标准库 unittest
scripts/          无依赖浏览器操作验证
docs/             MVP 规格与架构决策
examples/         数据模板
```

API 清单和选型口径见 [docs/architecture.md](docs/architecture.md)。所有页面、字体和图表均不依赖 CDN，运行期间无外部网络请求。

MVP 默认监听本机，适合个人评测与比赛演示。若需要内网试用，可通过 `--host 0.0.0.0` 监听网络接口；多人正式部署前应接入公司身份网关和 TLS、限制写入权限并替换为生产 HTTP 服务。当前版本不提供用户鉴权、权限管理、自动模型调用或第三方数据同步。
