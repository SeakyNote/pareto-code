# 确定候选配置覆盖与最小证据规模

Type: grilling
Labels: wayfinder:grilling
Status: open
Parent: ../map.md
Blocked by: 01, 02, 09

## Question

首版要支持什么选型主张：跨模型选择、同模型推理强度选择，还是二者择一？需要多少候选配置、SVG 任务和重复记录才能支持有限但真实的演示？

需区分理想覆盖和硬性最低覆盖，明确不承诺统计显著性或全面模型排名。用户先确定覆盖优先级；具体配置名单与样本数需在数据和评分路线明确后核验，不能先承诺未经测算的调用量。

建议讨论起点：优先少量可比配置，展示至少存在真实取舍的选型问题，而非单纯扩大模型数量。

## Dependencies

先确定[数据路线](01-data-route.md)和[评分依据](02-quality.md)，并取得[CodexRadar 快照核验结论](09-codexradar-evidence.md)，再锁定可兑现的覆盖和规模。核验未通过时按已确认退路评估自建评测，不能默认第三方数据可用。
