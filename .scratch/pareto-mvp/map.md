# 基于帕累托前沿的 AI 编码效费比评估与智能选型：MVP 决策地图

Labels: wayfinder:map
Status: open

## Destination

形成面向开发者、可交给开发实施的 MVP 规格：明确范围、评估证据与比较口径、帕累托前沿与选型规则、主要交互及可验证的验收标准，使实施前的关键决策不再悬而未决。

## Notes

- 使用 wayfinder 推进规划；当前地图不包含产品实现。后续规格存放于本目录的 `spec.md`，目前尚未形成。
- 每次处理人工参与的决策，使用 grilling 与 domain-modeling 技能；研究使用 research，交互探索使用 prototype。
- 用户已确认的起点（绘图前对话，2026-10-26）：终点是 MVP 规格；面向开发者的实用工具；在任务开始前提供选型建议；比较模型及其调用配置；先导入已有评测数据，不新增付费调用。
- 根 `GLOSSARY.md` 记录已明确术语；比较口径的完整决策与讨论进展见[什么样的评测记录可以比较，效果、费用和耗时各代表什么？](issues/03-comparison-and-metrics.md)。
- 本地图使用本地 Markdown tracker；子票据位于 `issues/`，通过 `Type`、`Labels`、`Status`、`Assignee` 与 `Blocked by` 表达类型、认领和依赖。`Blocked by` 中的编号仅是机器可读关系，正文引用一律用标题链接。
- frontier 为按编号排序、状态为 open 且所有阻塞票据均 resolved 的子票据。研究票据先认领再调查；每个会话最多解决一张非研究票据。
- 研究应区分可直接取得的数据、能够推导的数据和缺失数据；不得将不同执行方式或不同任务集上的数字未经论证地拼成同一候选方案的测量结果。
- 研究资产存放在 `research/`；按技能要求保留独立 `research/<name>` 分支及上下文指针，不开 PR、不合并。若远程发布受限，明确记录本地成果和实际阻碍。

## Decisions so far

<!-- 仅索引绘图后已解决的子票据；细节只保存在各票据的 Answer。 -->

- [哪些已有评测数据能够支持模型配置的可信比较？](issues/01-existing-evaluation-data.md)：已核实四类公开来源；Aider 有历史三维记录，其余来源存在费用、生成计时或执行环境匹配缺口，需据此决定首版任务与比较口径。
- [MVP 首先服务哪类编码任务与选型需求？](issues/02-first-task-scope.md)：首版以 Aider 练习编辑历史证据服务小型代码修改的任务前选型；用户主动选择评测场景，未覆盖需求显示证据不足，不预测具体请求结果。
- [什么样的评测记录可以比较，效果、费用和耗时各代表什么？](issues/03-comparison-and-metrics.md#answer)：采用严格比较组及效果、历史费用、调用耗时三维权衡；仅完整且证据合格的记录进入前沿，明确缺失值、不确定性和历史日期边界。
- [怎样从可比较的候选方案得到可解释的前沿与选型建议？](issues/04-pareto-and-selection.md#answer)：证据准入与硬约束筛选后计算三维前沿，保留并列及全部权衡选项；区分证据不足、约束无解与唯一可行候选，并提供可追溯的建议和排除理由。

## Out of scope

- 本轮地图不包含产品代码实现、上线或部署操作；终点是开发所需的 MVP 规格。
- MVP 不新增付费模型调用，也不建设实际运行编码任务的在线评测服务；证据从已有评测数据导入。
- MVP 不自动调用所选方案执行用户编码任务；用户依据建议自行决定采用方案。
- MVP 不比较完整编码工具或订阅套餐；比较对象是模型及其调用配置。
