## Question

和用户确定 MVP 接受的导入方式与最小数据契约：必须字段、可选字段、来源与日期、候选方案身份、比较组和指标单位。确定是支持少数来源的适配还是通用模板，以及谁准备和导入数据。

以[什么样的评测记录可以比较，效果、费用和耗时各代表什么？](03-comparison-and-metrics.md#answer)已确定的证据准入与指标含义为约束，落实关键配置、严格比较组、完整题数、三维指标、零费用依据及评测日期的校验。区分评测日期与数据获取日期，核对实际来源能够形成哪些合格比较组及候选数量；不因来源已选定就默认全部记录可比。

明确重复记录、同名不同配置、无效数值、单位不一致、缺失指标和更新数据时的处理方式；定义从图表或选型建议追溯到原始证据的最低要求。可用一个小型数据样例检验规则，但不实施正式导入系统。

同一候选方案的多次评测保留各次记录，不挑最高分、不直接混合平均；本票需明确去重与选取规则，并保留可追溯的依据。缺少必需证据的记录可供查看及说明缺失原因，但不进入前沿或选型建议。

## Answer

2026-10-26：经用户两轮确认，确定首版导入与证据契约。沿用[什么样的评测记录可以比较，效果、费用和耗时各代表什么？](03-comparison-and-metrics.md#answer)及[怎样从可比较的候选方案得到可解释的前沿与选型建议？](04-pareto-and-selection.md#answer)的准入、指标、前沿及历史证据边界。

### 导入责任与范围

- 项目维护者整理、审核 Aider 历史证据，提供带版本的初始数据；使用者可导入相同格式的 JSON 文件。
- 首版只定义一种通用模板，不做自动抓榜、多来源适配器或付费调用。来源原始 YAML 由整理者映射成模板，不承诺直接导入原始榜单格式。
- 文件包含格式版本、数据版本、来源资料引用及评测记录集合。格式版本供解释模板；数据版本区分证据更新，不能混用。
- 原始 token 用量、逐题结果、日志等是可选补充，不强制来源提供其没有的明细。

### 最小记录契约

区分“可以保存查看”与“可以进入比较”。每条可识别记录须能在本次导入中定位，并保留以下栏目；未知值显式为空，不伪造身份、条件、日期或指标。缺少来源运行标识时，导入内位置只供定位，不能当成已证明的跨批次运行身份。只有必需证据齐全且校验合格，才可进入前沿与建议。

| 类别 | 栏目与准入要求 |
| --- | --- |
| 来源运行身份 | 来源标识、来源内运行标识；不得用模型名或日期代替运行身份 |
| 候选方案身份 | 模型及版本、推理强度、采样参数、编辑格式等有效调用配置及其依据；参数不适用须有依据，不能把未知当默认；同名不同配置分别作为候选；首版排除主模型与编辑模型组合 |
| 比较组条件 | 任务集及版本、完整题目范围、Aider 版本与提交、测试及反馈规则、最大尝试次数；须有可追溯依据，不能只信任填写的组名或组编号 |
| 题目覆盖 | 实际完成题数、总题数；准入要求完整覆盖同组题目，不能仅凭相同题数推定相同题目范围 |
| 评测效果 | 来源报告的最终通过比例及精度；若来源提供通过题数则一并保留，不从四舍五入后的比例反推题数 |
| 历史评测费用 | 包含失败题及重试的整轮历史 USD 费用及口径依据；零值另须实际免费依据 |
| 平均调用耗时 | 来源报告的平均每题模型调用过程秒数及口径依据，不混用测试执行耗时、首 token 延迟或完整任务耗时 |
| 日期 | 评测日期、数据获取日期，保留来源精度与日期含义；不能用获取日期补评测日期，未知评测日期不准入 |
| 证据定位 | 来源链接、固定版本或内容指纹、来源快照、原始条目位置，以及关键身份、比较条件和指标的证明资料 |

只写汇总历史费用但没有 token 明细时，可以按前置决策接受，注明“来源报告值，未独立复算”。未提供的参数、题集版本或运行规则不能由导入程序猜测；来源代码中的默认值也不能单独证明某次运行实际使用的配置。

### 校验、单位与导入确认

1. 文件不可解析或格式版本不支持时整份拒绝，说明文件级错误。
2. 可识别的记录逐条校验并预览，列出可准入记录、证据不足记录、非法数值、冲突及重复项；展示各类数量与具体原因，再由导入者确认保存。不静默修补、丢弃或覆盖。
3. 能保存查看的不完整或无效记录仍明确标记问题，不进入建议。无法识别为记录的内容在导入报告中定位其错误，原文件保留；不能因为保留了原文件就视为已成功解析。
4. 模板指标统一为百分比、USD、秒。其他单位由整理者明确换算，保留原值、原单位与换算依据；不自动换汇，不按当前价格重估。非标准单位未明确转换时不能准入。
5. 通过比例须为有限数值且在 0—100% 内；费用与耗时须为有限非负数。拒绝负值、NaN、无穷大及无法解释的数值。缺失值不填零；零费用必须有可信免费依据。
6. 完成数、总题数及可选通过数须为整数；完整评测要求总数为正，且 `0 ≤ 通过数 ≤ 完成数 ≤ 总数`。部分完成或题目范围未证明的记录仅供查看。
7. 同时提供通过题数和通过比例时，按来源报告精度核对；来源舍入可以解释的差异不算冲突，不能解释的不一致须标记冲突。保留来源精度，不增加虚假精度；展示舍入不改变比较结果。

### 去重、冲突与版本更新

- 同一次评测按“来源＋运行标识”识别；候选方案身份与运行身份分开，同一候选可以有多次运行，同一天也可以有多次运行。
- 同一运行、同一内容再次导入时不新增评测，保留其与新导入批次的关联。
- 同一配置的另一次运行独立保留，不挑最高分、不混合平均，不因指标相同就去重。
- 同一运行出现不同指标或配置时，保留各版本及来源，标记冲突；在明确确认修订和依据前，该运行暂停参与前沿与建议。不能用后导入版本静默覆盖，不能把同次运行的修订伪装为一次新运行。
- 已确认的修订保留其前后版本及修订依据。每次建议须可定位当时选用的证据版本；后续重新计算须应用当前校验与冲突状态。
- 无法确认两条资料是否指向同次运行时，不擅自去重或认定为两次独立运行；保留身份未核实说明，待补证后再准入。

### 重复评测的选择顺序

在用户所选的严格比较组内：

1. 校验身份、分组、完整题目范围、三维指标、日期和证据，排除不合格及未解决冲突的运行。
2. 对每个候选方案，默认选评测日期最新的合格记录。
3. 对选定记录应用用户硬约束，再计算帕累托前沿。

选择运行发生在约束筛选前，不能为了满足预算或最低效果自动换成旧运行。所有其他运行仍可查看；用户可以明确改选历史运行，建议中显示本次具体选择。日期只有“日”等精度、无法判断多次运行先后时，要求明确选择，不按分数、导入时间或任意顺序选一个。改选记录不改变严格比较组与证据准入要求。

若存在更新但不合格的记录而沿用旧记录，说明旧记录的日期、更新记录为何被排除以及当前选择依据，不把它标为最新运行或当前模型表现。

### 从建议追溯到证据

- 每次导入保留原文件、导入批次、数据版本及逐条校验结果。整理后的 JSON 与其引用的原始来源快照分别留存，不能用整理文件替代原始证据。
- 每个图表点及选型建议可沿“候选及所选运行 → 证据版本 → 来源快照及原始条目 → 原始链接”追溯，显示评测日期、获取日期及关键配置/分组证明。
- 快照应能在保存的资料中离线定位；持续变化的来源网页不能替代快照。快照、批次与条目如何持久化，由[哪种运行方式与技术边界足以支撑这套 MVP 流程？](07-delivery-and-architecture.md)决定，不在本票决定产品整体离线运行或部署形式。
- 更新新增版本，既有证据不静默覆盖；三项指标均保留其来源口径、精度及已知限制。

### 用假设记录检查边界

以下仅用于检查契约，不代表真实模型证据：

| 情形 | 预期结果 |
| --- | --- |
| 同一运行、同一版本重复导入 | 只保留一条评测，关联两次导入批次 |
| 同一候选两次合格运行，较新一次费用更高且超过用户约束 | 默认选较新一次，再按约束排除；不自动换成便宜的旧运行 |
| 同一天两次合格运行，来源没有更细时间或可信先后依据 | 要求明确选取，不挑效果高的一次 |
| 同一运行的费用一处为 $10、另一处为 $12，尚无修订依据 | 保留版本并标记冲突，暂停该运行参与建议 |
| 新运行缺少耗时，旧运行合格 | 新运行仅供查看；可沿用旧运行，但说明日期及更新记录缺失的证据 |
| 题数都是 225，但任务集版本或题目范围无法证明一致 | 不能仅凭题数归为同一严格比较组 |
| 费用为零而没有实际免费依据 | 按费用未知处理，不参与建议 |
