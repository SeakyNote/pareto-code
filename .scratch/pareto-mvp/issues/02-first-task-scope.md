# MVP 首先服务哪类编码任务与选型需求？

## Question

结合数据可用性，和用户决定首个可验证的编码任务类别、目标开发者的具体选型时机，以及用户输入的需求如何映射到已有评测覆盖的场景。

用至少一个具体使用故事明确系统能承诺什么，如何处理已有数据未覆盖的语言、任务或难度，以及哪些任务不属于 MVP。区分“某类任务上的历史证据”与“预测某个具体请求的结果”，避免默认为每个开发任务都能给出可靠估计。

## Comments

2026-10-26：用户在第一轮讨论中确认：

- 首版聚焦有测试的小型代码修改，以 Aider polyglot 的练习编辑评测作为证据；算法题生成、真实仓库 issue 修复暂不纳入首版。
- 首版提供历史评测中的模型配置选型参考，不预测用户某个具体请求的成功率、费用或耗时。展示证据覆盖范围与评测日期；遇到未覆盖的任务、语言或配置，说明证据不足。现有 Aider 汇总数据不足以支持按语言给出成绩。

2026-10-26：用户在第二轮讨论中同意具体使用故事，以及由用户主动选择已有评测场景、未覆盖需求显示证据不足的边界。两轮共四项选择均获用户确认，决策已收敛。

## Answer

2026-10-26：经与用户两轮讨论，确认以下首版范围与使用故事。

### 首个任务与目标用户

面向准备开始编码任务、需要选择模型及其调用配置的开发者。首版聚焦有测试的小型代码修改，以 Aider polyglot 的练习编辑评测作为历史证据。该基准的成绩代表其练习编辑场景，不据此承诺所有小型修改任务都能获得同样结果。

### 具体使用故事

开发者准备修改一段已有测试的小型函数，在开始前比较模型及调用配置，依据历史效果、费用和耗时权衡选择。系统展示建议理由、评测日期及适用边界，由开发者自行采用。

故事的可验证结果是开发者能够基于可追溯的历史证据理解候选方案的权衡并自行选择；不是系统执行修改，也不是验证该用户请求的实际完成效果。具体指标、推荐规则和交互呈现由后续票据决定。

### 需求与证据的对应方式

- 用户主动选择已有的评测场景；首版提供 Aider polyglot 练习编辑场景的整体证据。
- 不通过粘贴代码或自然语言描述自动判断任务类别、难度并匹配成绩。
- 展示证据覆盖范围和评测日期；汇总成绩不推导为特定语言或难度的分项成绩。
- 对没有对应证据的任务、语言、难度或模型配置，明确显示“证据不足”。用户仍可主动浏览历史结果，但系统不将其标为该需求的适用推荐。

### 产品承诺与范围边界

提供历史评测中的模型配置选型参考，不预测用户某个具体请求的成功率、费用或耗时。算法题生成和真实仓库 issue 修复不属于首版任务范围。
