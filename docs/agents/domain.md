# Domain Docs

## Layout

This repo uses a single context:

- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the area being explored.
If they are absent, proceed silently. The domain-modeling skill creates
them when terms or decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. If a required term is missing, reconsider the term
or note the gap for domain-modeling.

## ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and the reason to reconsider it.
