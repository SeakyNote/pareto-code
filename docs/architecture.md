# MVP 规格与架构决策

## 验收范围

首个完整场景是**代码开发中的 Python 代码审查**，以固定测试集中的缺陷定位任务为准，不把该分数称为通用模型智力。流程为：导出评测任务 → 在使用的模型 / Agent 中执行 → 记录完整响应、执行起止时间与账单费用 → 规则评分并入库 → 在同口径组内按效果、费用、耗时计算三维帕累托前沿 → 输入约束并比较推荐 → 导出结果。

演示数据只用于体验界面与算法，使用合成配置与指标，**不是公开榜单、真实报价或实测结论**。真实数据和演示数据始终分开。真实数据库初始为空。不自动采集第三方网站，不调用收费 API，不将员工代码发送到外部服务。

## 已作决策

1. 使用 Python 3.11+ 标准库 HTTP 服务、SQLite、原生 HTML/CSS/JavaScript。无前后端安装依赖、无需密钥，适合 MVP 离线试用。单机浏览器/服务端架构，默认仅监听 127.0.0.1。
2. 采用同场景、任务集、评分方法、耗时口径、成本口径、渠道和数据性质组成的比较组。不跨组归一化评分；必要指标缺失的记录单独列出。
3. 效果越高越好；平均每任务人民币费用、从发起到完整返回的平均每任务执行秒数越低越好。相等的配置不互相支配。计算使用原始精度，显示四舍五入。
4. API 成本采用实际账单人民币费用；若自行按 token 计算，需自行纳入输入、输出、推理、缓存及汇率，记录在成本说明中。订阅成本采用月费 / 预计月任务量，不等同于边际调用费用或可用额度承诺；两种渠道不混排。
5. 推荐先满足质量底线、费用上限与时间上限，再在前沿上选取最低费用、最低最大归一化遗憾（均衡）、最高效果三档。均衡指标为三个目标各自距最优值的比例差中的最大值；零跨度维度记 0。它是透明的规则推荐，不冒充 AI 解释。
6. 约束无解时只展示可调节方向，不擅自放宽约束或推荐不达标配置。月任务量影响月度估算及订阅摊销；节省测算仅在推荐质量不低于基准质量时给出。
7. 评测导入采用事务性追加；重复 ID 拒绝，不覆盖已有记录。相同配置、同口径多次快照仅用最新有效快照参加选型（即使最新快照指标缺失，也不会悄悄回退），历史记录保留在数据页。
8. 自建评测以固定 JSON 缺陷标签与行号校验，惩罚误报，不执行模型生成的代码。公开测试只是初始基准，无法杜绝污染；后续需持续维护隐藏集与人工校准。

## 数据与接口

SQLite 的 records 表保留完整 JSON、导入时间和主键。配置维度包括模型、模型版本、Agent、推理强度、供应商和渠道。每条记录有数据来源、评测时间、样本数、评分规则、成本说明。JSON / CSV 使用相同结构，详见 README。请求大小最多 2 MiB、每次导入最多 500 条。

- `GET /api/health`：服务就绪状态。
- `GET /api/catalog`：场景、比较组、记录统计。
- `GET /api/records?dataset_kind=demo|measured`：原始记录（含历史）。
- `POST /api/analyze`：同口径选型、前沿、分档推荐、基准测算、排除原因。
- `POST /api/import`：JSON/CSV 校验预览与事务导入，`dry_run` 控制。
- `GET /api/benchmark`：导出不含答案的固定评测任务与结果模板。
- `POST /api/benchmark/score`：离线结果评分，返回待导入记录与逐题反馈，不自动入库。

静态页面同源访问 API；写请求验证 Origin / Fetch Metadata，仅接受 JSON。无鉴权、默认本机使用；内网多人部署前需接入公司身份网关、TLS、权限及备份，标准库服务器也应替换为生产服务。此边界不影响本地 MVP 闭环。

## 验证

标准库 unittest 覆盖支配关系、相等点、三维权衡、随机性质、边界约束、零费用、比较组隔离、缺失指标、快照、订阅摊销、预算与同质量节省、导入原子性、评分和 HTTP API。使用本地 Chromium 验证界面、真实导入、空结果、键盘交互及移动端布局。
