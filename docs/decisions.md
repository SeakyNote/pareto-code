# MVP 架构与产品决策

依据：`方案/AI应用大赛参赛方案介绍.md` 与 `方案/image.png`。本文件记录本次 MVP 的落地取舍，便于后续人工审阅和迭代，不代表已经执行未安装的 Wayfinder 工具。

## ADR-001：先完成代码开发的完整选型流程

方案要求至少打通一个核心场景。优先交付代码开发；其他三个场景共享数据模型和算法，导入相应评测即可使用。首版以导入评测为入口，不把自动抓取和付费跑分作为启动前提。

仓库没有可导入的原始评测文件。原型图只说明交互方向，不能证明完整配置的三维指标。因此内置人工演示集，统一标记 `source.type=demo`，不声称重现 CodexRadar 原始数据、官方报价或实测节约比例。

## ADR-002：B/S 架构，单进程 Node.js 与 SQLite

使用 Node.js 内置 HTTP 服务与 SQLite；前端采用浏览器原生 ES Modules 和 SVG。无构建步骤、CDN、网络字体或运行时第三方依赖，便于在内网快速演示。算法独立于 HTTP 与数据库，可后续迁移到其他服务。

SQLite 持久化快照、配置与导入历史；浏览器只保存当前快照与渠道下的固定对比项。过滤条件写入 URL，可刷新复现。服务器默认监听本机；首版不提供多租户、账号或权限隔离。

## ADR-003：严格隔离快照和使用渠道

快照标识一组声明为同口径的数据：同场景、任务集、评分规则、分数上限、聚合口径、完整执行耗时口径、费用单位与币种；快照同时固定来源和评测时间。相同 id 不允许再次导入，CSV 中相同 id 的元数据不一致时整批拒绝。

模型版本、Agent、供应商、推理强度与渠道保留在每条配置中。API 与订阅分别比较，不把实际 API 单次费用和用户假设的订阅均摊费用混为一谈。不同币种不自动换算。实验真实性与“同任务集”的实际一致性仍需数据提供者审查；系统不把格式正确等同于评测可信。

必要指标缺失、非完整耗时、非所有任务均值、非每任务费用，以及缺少链接的第三方快照，单列展示，不用于排名或推荐。失败任务需要按同一规则计入分数和费用 / 耗时均值，不能仅报告成功任务。

## ADR-004：三目标确定性筛选，权重仅用于分档推荐

支配关系：`a.quality >= b.quality && a.cost <= b.cost && a.duration <= b.duration`，且至少一项严格不等。全等配置互不支配。算法复杂度 O(n²)，每次导入最多 2000 条配置；每条最多返回 5 个支配示例，避免响应无限增长。

前沿先在同一快照、同一渠道的完整数据中计算；再按用户的费用上限、耗时上限、效果下限筛选可行集合，计算其前沿用于推荐。这些单调约束下，支配者若存在也满足相应约束。切换偏好不改变前沿。

经济档选择费用最低（同价时先耗时、再效果）；效果档选择效果最高（同分时先费用、再耗时）；偏好档对可行前沿内的效果、费用、耗时做 min-max 归一化，按显式权重相加。相同维度值统一记为 1，避免除零。最终以配置 id 打破完全相同指标的平局，保证结果可复现。

图中圆环标记三目标前沿，虚线仅表示二维包络；第三维耗时另外由点大小、详情和表格展示。对数坐标采用 `log1p(x / unit)`：费用单位 0.01，耗时单位 1 秒，保留零费用；它只改变显示位置，不改变计算。

## ADR-005：订阅成本是透明的使用假设

会员均摊费用 = 月订阅费 / 每月有效任务量。任务量必须为正整数，月费可为零；同一快照、同一会员渠道应用同一组均摊假设。月费币种沿用该快照币种。

本口径不等同于任务新增支出，不保证配额、排队、团队席位、复杂任务折扣或超额费用；这些需要未来扩展计划、额度与使用记录模型。默认值不是实际会员定价。

## ADR-006：先提供规则解释，不伪装为 AI 推理

首版费用计算、帕累托与推荐均为确定性实现，解释公开规则，不需要密钥或远程调用。后续可加需求解析和解释服务，但应保留数学结果作为唯一筛选依据；AI 判分需要另行建立任务规则、人工抽查和版本记录。
