# 方案概述

本方案面向公司内部使用付费 AI 的员工，针对实际工作中 Agent、大模型、推理强度及使用渠道组合繁多、选型缺乏客观依据、效果与成本难以兼顾等问题，拟建设基于帕累托前沿的 AI 应用效费比评估与智能选型系统。系统暂定采用 B/S 架构，后续可根据实际体验灵活调整；通过结合高可信度的第三方评测数据与贴合业务的自建测试集，从任务效果、执行耗时和调用费用三个维度评估不同模型及配置的表现。用户选择目标场景并提供预算及时间要求后，系统自动计算并可视化展示帕累托前沿与分档推荐方案，辅助用户权衡决策。项目开发采用 Matt Pocock 的 Wayfinder 等工程化 AI 辅助工作流，由人工把控关键决策与交互验收。系统落地后，预期将帮助员工缩短选型与试错时间，在保障产出质量的前提下大幅减少不必要的 AI 资金支出。

# 方案创新性

目前员工主要通过人工对比各大公开 AI 评测榜单来选择模型，但在实际应用中存在明显局限：

1. 开源评测榜单普遍存在“刷分”问题，部分模型沦为“做题家模型”，实际使用体验与榜单排名明显不符，表现为“高分低能”。
2. 闭源评测榜单的公信力与透明度难以验证，且其评测内容与用户期望对比的具体业务需求未必一致。
3. 用户投票型榜单中，输出风格迎合、讨巧的模型更容易获得高分；同时此类榜单交互轮次较少，难以准确评估复杂工作任务中的真实生产力。
4. 综合型榜单通常按自行设定的评价权重汇总得分，主观性较强，难以契合不同用户的实际预期。
5. 各榜单评估结果发布后一般不再动态更新，无法及时反映模型后续因算力调整或版本暗改导致的“降智”问题。
6. 同一模型在不同推理强度下的表现与开销差异显著，实质上可视为不同模型，但大部分榜单对单个模型的推理强度覆盖并不全面。
7. 现有评测榜单大多仅按分数排名，或将资金消耗与时间消耗分别罗列，缺乏综合权衡。例如部分国产模型依靠极长思考时间堆砌分数，俗称“雷霆大思考”，在实际工作中既昂贵又低效。

近期业界最接近本方案的已有系统为 CodexRadar 网站，但该网站仅评估 GPT 系列模型，且测试重点局限在 SVG 绘图和逻辑推理，其他日常研发与办公场景较少涉及。

针对上述问题，本方案拟从以下四个方面形成创新：

1. **结合实际工作场景开展评测** 数据来源一方面引入较可靠、与实际使用体感相符的第三方评测结果，另一方面围绕代码开发、SVG 绘图、办公自动化和文档编写与审查等高频场景自建测试集与任务，从源头杜绝“刷分”，使评估结果更贴合实际工作需求。
2. **基于帕累托前沿进行多目标选型** 将 Agent、基础模型、推理强度及供应商等不同组合作为候选配置，在统一口径下综合比较任务效果、调用费用和任务耗时，筛选处于帕累托前沿的方案。在当前可比配置中，若不存在另一个配置能在效果不降低、费用和耗时不增加的情况下至少有一项更优，该配置即处于帕累托前沿。用户可根据具体场景、预算和时间要求，从多个各有优势的前沿方案中按需选择，而不必依赖单一榜单分数。
3. **利用 AI 辅助评估与选型解释** 在评测环节，对可自动验证的任务采用明确规则判分，对需要主观判断的任务探索结合 AI 辅助评分与人工抽查校准；在选型环节，利用 AI 辅助识别用户的场景需求、解析多维评测数据，并生成直观的选型建议与推荐理由，提高评测与选型效率。
4. **支持评测范围扩展与工程化开发迭代** 尽可能涵盖常用 Agent、模型和推理强度，结合不同供应商及使用渠道的数据按需更新评测结果，为后续接入更多场景和配置预留扩展空间。同时，项目自身基于 Wayfinder 工作流推进，通过记录架构决策、拆分需求规格并引入人工审查，使 AI 辅助开发过程更加清晰可控；相较于直接向 AI 提出模糊需求的“许愿式编程”，该方式更有利于需求与实现对齐，也提高了开发过程的可追溯性。

预期解决的问题与核心效果：
1. 通过自建测试集杜绝模型“刷分”与“高分低能”情况；
2. 保障评测结果的可信度与实际工作场景的相关性；
3. 支持按需更新评测数据，及时识别并规避模型“降智”问题；
4. 尽可能涵盖常用 Agent、大模型及不同推理强度档位；
5. 综合权衡任务效果、金钱成本与时间成本。

# 场景适配性

本方案面向使用付费 AI 的公司员工，计划覆盖代码开发、SVG 图片与流程图绘制、办公自动化、文档编写与审查等高频场景。用户在不同任务中需要选择 Agent、模型、推理强度和使用渠道，但现有公开评测结果与实际业务需求往往存在偏差，容易出现模型榜单分数较高但实际工作效果不理想，或者为简单任务支付不必要溢价的情况。

如下图所示，某同事的 API 用量记录中，近 7 天请求 16,253 次、消费 299.85 元，说明付费 AI 已在实际工作中高频使用，并会持续产生费用。当模型及配置选择不合适时，资金费用和使用效果均存在明显的优化空间。

![[Pasted image 20261101153653.png]]

实际使用时，用户只需选择具体工作场景，并填写预算范围、可接受的任务耗时等需求。系统随即调取对应场景的最新评测数据，综合比较不同配置的任务效果、费用和任务耗时，直观展示帕累托前沿上的候选方案及推荐理由，供用户结合自身经济能力与任务需求快速选择。

在人机分工方面，系统利用 AI 辅助理解用户需求、参与主观任务评估、解析评测结果并生成选型解释；费用核算、耗时统计和帕累托前沿筛选等可量化内容，均由确定性规则和数学计算方法处理，最终选型由用户拍板完成。项目建设过程中的关键决策、规格文档审查和阶段性体验测试由人工主导参与；最简可行产品完成后，将探索利用 AI 进行系统的自动化迭代。

在场景与渠道边界上，最简可行产品将优先打通上述场景中至少一个核心场景的完整选型闭环，其余场景后续按需横向扩展。评估模型范围暂定为主流大模型，使用渠道涵盖正价 API 渠道和 GPT 会员订阅渠道，不同渠道的费用将分别建立清晰的计算与折算口径，并为后续扩展预留空间。

# 落地可行性

**技术方案与开发方式** 系统暂定采用 B/S 架构：前端负责接收用户的工作场景、预算和任务耗时要求，并可视化展示帕累托前沿与候选方案；后端负责汇聚清洗第三方评测数据与自建测试结果，比较不同配置的任务效果、费用和耗时，计算帕累托前沿并提供选型建议。前期已通过 One-shot 生成项目，并借助 grill-with-docs 制作早期界面原型供参考研究，原型图片见“方案创新性”章节。后续拟通过 Matt Pocock 的 Wayfinder 工作流推进，依次完成交互式决策记录、生成规格说明、拆解实施工单、AI 编码与测试审查，再结合人工体验持续循环迭代。最简可行产品完成后，技术架构可根据实际体验通过 AI 辅助灵活调整。

**评测数据比较口径** 第三方评测和自建测试结果将按业务场景、任务范围及评分标准归类，完整记录数据来源、评测时间、模型及版本、Agent、推理强度和使用渠道。其中，模型智力指数指模型在特定评测任务和评分规则下得到的能力量化指标，用于反映其在相应任务范围内的表现；可比的指数作为任务效果评价的参考，结合具体场景的任务表现使用，不代表模型在所有任务中的统一能力。系统仅在同一场景下对任务要求、评分标准以及费用和耗时统计口径一致或可验证对齐的配置开展帕累托比较；暂不具备可比条件或缺少必要指标的数据将单独展示并注明原因，待补充或口径对齐后再纳入对比。

**耗时统计口径** 用于帕累托比较的任务耗时，严格定义为从发起任务到模型或 Agent 返回完整结果所用的执行时间；员工日常查找、比较和试用模型所花费的时间，则作为选型效率指标单独评估。

**资源条件与实施计划** 研发所需基础工具已具备，目前已拥有 GPT 会员订阅，计划使用 Codex 进行编码开发，后续将根据实际评测需求合理控制 OpenRouter API 调用额度。第三方评测数据的获取方式、自建测试集细节、模型调用条件及各渠道费用折算口径将在实施过程中进一步确认。实施周期上，计划利用两周业余时间完成最简可行产品：前期明确场景、评测数据口径和技术方案；后期打通数据整理、帕累托筛选算法和页面展示，优先完成至少一个典型场景及主流模型配置的选型流程，其余功能按需持续迭代。

**主要风险与应对** 一是自建测试集的评测费用需在初步测试后确认，非订阅正价 API 存在耗资超出预期的可能；后续将通过合理控制测试集难度、分批测试、优先覆盖常用配置、设置费用上限及探索低成本模型辅助评估等方式控制投入。二是实施周期较为紧张，近期需在客户现场驻场，日常工作繁忙，无法在工作时间开展相关研究与开发，且业余时间还需兼顾个人婚礼筹备及公司招聘等事务；若进度紧张，将优先保障核心选型主流程的高质量落地，将其余非核心需求留待后续版本迭代。三是对于部分数据暂不可获取或口径不一致的情况，优先使用已获得的同口径基准数据，并在界面显式标注来源与快照时间。

# 实际价值

在同等工作量、任务产出达到相同质量要求的前提下，本方案将可比的模型智力指数作为任务效果参考，综合比较不同 Agent、模型、推理强度及使用渠道的任务效果、费用和耗时，辅助用户切换至帕累托前沿上的高性价比配置，预计可将日常 AI 使用成本减少一半以上。该测算依据来源于个人在实际项目中人工模拟模型切换的使用经验；对于尚未系统研究过模型选型的同事，预计成本节约空间更大。系统完成后，将通过相同任务在原有惯用配置与系统推荐配置下的实测对比，完整记录费用、任务效果和耗时，量化验证实际节约幅度。

在效率与质量方面，方案可显著减少员工查找、对比与盲目试用不同模型所耗费的时间，帮助用户避开榜单得分较高但实际表现不佳、不适合当前工作场景的“高分低能”模型，避免“一招鲜”式的资金浪费，并消除不可靠榜单的误导。

在投入产出方面，员工自费使用时，收益直接体现在个人 AI 经济负担的降低；若公司采取部分报销或全额统一支付策略，则可直接减少公司层面的 AI 费用支出。项目建设过程中的测试集构建、评测消耗和系统维护等投入将单独记录，用于后续客观评估整体投入产出比。

# 推广潜力

本方案以公司内部推广为主，目标是面向有付费 AI 使用需求的员工实现内部全覆盖。最简可行产品完成后，计划先在小范围内开展试用，根据用户反馈完善评测维度和选型功能，再逐步推广至更多部门和项目，并根据实际条件部署到公司内网。

系统的数据管理、帕累托选型计算和结果展示等核心能力均支持跨场景复用。后续新增业务场景时，主要按标准补充相应的测试任务、评测规则和基准数据，无需从头重构整套系统，复制与扩展成本较低。日常推广投入主要包括评测数据收集与更新、模型评测调用和基础系统维护；内网部署仅需具备相应的数据访问与模型调用条件即可落地。

无论公司对 AI 工具采取员工自费、部分报销还是全额支付策略，方案均可通过优化模型选型，持续减轻员工或公司的资金负担。随着大模型和业务场景不断演进，系统将按需更新评测数据和选型建议，逐步为公司沉淀出贴合业务的测试集、评价方法及模型选型经验，形成公司长期 AI 应用资产。通过持续更新，预期项目价值不会随着 AI 技术迭代而衰减。
