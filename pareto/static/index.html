METHODOLOGY / 04

让取舍透明，让推荐可解释.

可量化的计算交给数学，最终的选择交给你。

THREE OBJECTIVES. NO SINGLE WINNER.

没有绝对最好的模型，
只有适合任务的配置。

如果找不到另一个配置能在效果不降低、费用和耗时不增加的同时，至少有一个指标更好，那么它就在帕累托前沿上。

任务效果 ↑ 更高每任务费用 ↓ 更低完整执行时间 ↓ 更短
01

先确认可以比较

仅比较同场景、任务集、评分方法、耗时统计、费用口径和使用渠道的数据。真实与合成数据严格分开。同配置取最新快照；缺少必要指标时直接排除，不自动补零。

02

三个目标，一起看

前沿按三个原始指标计算。图上横轴与纵轴只展示两个维度，气泡大小表示执行耗时；二维投影中看似不占优的点，也可能因为第三个维度而在前沿。相同点不互相支配。

03

推荐规则完全公开

先筛选满足全部约束的配置，再从前沿中给出最便宜、均衡及效果最高三档。均衡使用三个目标的最大归一化遗憾最小原则，范围由可行前沿决定，零跨度维度记 0。不满足约束时不给强行推荐。

regret = max(效果差距, 费用差距, 耗时差距)
各差距 = 距该目标最优值 / 该目标跨度
04

两种费用，分别算清

API 使用单任务真实账单费用；会员采用月费 ÷ 预计月任务量，两者分开比较。会员摊销只是费用分配假设，不代表边际费用、无限调用或可用额度；预计月任务量改变时即时重算。

05

节省金额，有质量前提

相对你选择的基准，只在满足全部约束且效果不低于基准的配置中，选择成本最低者估算节省金额。没有达标方案就明确显示暂无。所有节省比例都只是当前数据和任务量下的估算。

06

知道分数的边界

自建 v1 是 8 道 Python 微型代码审查任务，包含 2 道无缺陷题；按每题 F1 评分，误报会扣分。格式错误记零分。题量小、公开集可能被污染，不能宣称杜绝刷分；建议后续增加隐藏集与人工校准。

此 MVP 的建议由确定性规则生成，未接入 AI 主观评分或自动外部数据采集。
